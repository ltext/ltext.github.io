Debugging

If you toyed around with the apply function from earlier, you may have seen a daunting error: 

$ ltext "\f -> apply f bar"
[Print Error] Can't print textual data while inside an expression:

    f [text from "bar"]

...cannot be rendered to a file.

This is intended! This makes sure that the templates we render are actually renderable.

In layman's terms, a template can only be rendered if all of its text ends up concatenated at the "top level". Here, after reducing the expression, the text of bar is still waiting to be passed to f - a function we don't know yet - so there's no way to write it out as a file.

We can still check the type of such an expression with --type, but to render it, we have to apply whatever is still missing first.

Other mistakes are caught before anything is rendered, too. Applying a file to the wrong kind of argument is a type error, a misspelled file name is an unbound variable, and a malformed expression - in a file's header or on the command line - is a parse error that names the file, line and expression at fault. Add --verbose to see how λtext reads each file.
